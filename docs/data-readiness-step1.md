## Acquisition rules

- **JPL planets and moons:** retain the dated discovery roster including provisional designations, physical tables, published ephemeris coverage and cited source models. Use Horizons for representative references and selected precise trajectories. Pin orientation kernels and keep body center distinct from system barycenter. Supply valid source frame, time scale and validity for usable positions.
- **JPL small bodies:** use the exact population filters in the table and probe log. Capture provider API version, acquisition interval, raw hashes and stable record ordering. Use full precision for later imports, preserving observation arc, last observation, solution epochs and uncertainty fields when available. Check reproducible ID/count reconciliation before promoting a paginated acquisition. JPL requires one request at a time, caching, application identification and backoff. MPC bulk orbit archive HEAD succeeded as a fallback and identity cross-check. Full MPC file format, body coverage and archive rights remain open.
- **Near-Earth artificial catalogs:** select Earth on-orbit SATCAT PAY records for satellites/stations, and Earth on-orbit R/B and DEB for the separate debris view. Keep status, orbit type, Earth versus other orbit centers, catalog age, and decayed records for reconciliation. Join an eligible public GP record on the full NORAD ID. Use modern CSV/OMM and record epoch and input model separately. Keep missing GP entries searchable. Fetch only needed products once per source update. CelesTrak documents a two-hour GP cadence, compressed CSV and stopping on failures. Space-Track documentation was reachable, while its account-required data remains outside the initial source selection.
- **Refresh:** preserve immutable dated releases. Review monthly for planetary rosters and cross-check changed mission archive versions before a body batch. For SBDB, start with a pinned acquisition to measure cost and choose a provider-compatible refresh interval in Step 3. Read archived inputs offline. Enforce orbit freshness separately from download freshness.
- **Reuse:** public read access doesn't settle binary redistribution. Track rights and credits per dataset/product, including identifier/version, third-party notices and derivative terms. Restrict GitHub and the dashboard to project-authored reports, URLs, aggregate observations and the request log. Confirm input and derivative reuse before distributing raw data or asset packs.

References: [JPL SSD API policy](https://ssd-api.jpl.nasa.gov/), [SBDB fields](https://ssd-api.jpl.nasa.gov/doc/sbdb_query.html), [SBDB filters](https://ssd-api.jpl.nasa.gov/doc/sbdb_filter.html), [CNEOS definitions](https://cneos.jpl.nasa.gov/about/neo_groups.html), [CelesTrak GP formats](https://celestrak.org/NORAD/documentation/gp-data-formats.php), [CelesTrak policy](https://celestrak.org/usage-policy.php), [PDS citations](https://pds.nasa.gov/datastandards/citing/) and [NASA media usage](https://www.nasa.gov/nasa-brand-center/images-and-media/).
